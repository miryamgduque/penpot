## Why this is a check and not a rewrite

This plan was scoped with a phase to "rewrite the Component factory skill, which misled the
agent into a `Property=Value` naming matrix". Reading the skill refutes that:

1. **The skill is already correct.** `penpot-component-factory` mentions
   `createVariantFromComponents` seven times and states the real workflow — build each variant
   as a board, then "combine them into a variant container
   (`penpot.createVariantFromComponents(boards)`)". It never suggests name-encoding.
2. **It is generated, and upstream.** `skills-core/src/aikit.gen.ts` is marked *"GENERATED by
   ai-skills/scripts/import-aikit.mjs — do not edit by hand"*, imported from the official
   [penpot-ai-kit](https://github.com/penpot/penpot-ai-kit). A hand-edit is reverted by the
   next import.
3. **The tool-surface mismatch is already handled.** The skill drives the MCP/plugin surface
   via `execute_code`, which the CLJS port deliberately dropped. `body-preamble`
   ([agent_skills.cljs:177](../../../../../frontend/src/app/main/data/workspace/agent_skills.cljs))
   already reframes exactly this at fetch time: *"Names like `execute_code` … are NOT tools you
   can call: reach for your own tools instead, and if a step needs a capability you genuinely
   lack, say so rather than pretending you used it."*

Point 3 explains the transcript. The agent followed the preamble **correctly** — it said it
genuinely lacked the capability instead of pretending. The `Property=Value` frames were its
own improvisation while reaching for a tool that did not exist. Phase 01 supplies it, and the
preamble's "translate onto your own tools" then has something to translate onto.

So the honest scope here is: confirm the translation actually happens. If it does, this phase
is a no-op and that is the correct outcome.

## If a patch turns out to be needed

Three routes, cheapest first. Do not reach past the first that solves it:

1. **Extend `body-preamble`** — one line mapping the stale call to the real tool, e.g.
   "`createVariantFromComponents` → your `create_variant` tool". Local, survives the next
   import, no generated file touched. Almost certainly sufficient if anything is.
2. **A local override at a more specific scope** — the cascade in `skills-core/src/resolve.ts`
   is built for this: *"The most specific scope that defines a name wins its body"*. Defining
   `penpot-component-factory` at `org`/`project` scope in `builtin.ts` overrides the platform
   body without editing the generated file. Heavier: forks a large body, which then drifts from
   upstream.
3. **Upstream to penpot-ai-kit** — correct if the skill is genuinely wrong for everyone, but
   the skill is not wrong; it is right for the surface it targets. Out of scope for piweek.

Route 2 is the one to be suspicious of. Forking a skill body to fix a tool-name mismatch trades
a small permanent maintenance cost for a problem route 1 solves in a line.
