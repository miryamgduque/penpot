What eleven open-source AI agents taught us

2026-07-19 · Three researchers pulled the actual prompt and config source files from each project's repo, and mapped what they found against our own architecture and our measured weaknesses (the Kahoot and NYT postmortems).

What's in the set: nine of the eleven are AI coding agents; only Onlook is a true design tool, with bolt.diy as a UI generator. So this is mostly a survey of agent architecture and prompting patterns that carry across domains, plus how rule-enforcement looks across the field, not a head-to-head of design competitors.

The one line that matters for the pitch

Every researcher independently confirmed the same thing: enforcing rules structurally, at the point a change is made, is rare even among these coding agents, and nobody does it for design. Roo Code is the only one enforcing anything at the tool (file restrictions); the two design-adjacent tools (Onlook, bolt.diy) rely on prompts and preview instead. That's the claim behind "Reason 1."

Where we were already ahead

  • Tool-boundary rule enforcement: a raw hex color is rejected by the tool itself, not merely discouraged in the prompt. Nobody else does this for design rules.
  • Visual self-review loop: the agent renders its own work and looks at it. Onlook, the closest cousin, leans on the user's live preview instead.
  • Graduated governance: suggest / apply-with-review / auto-fix. Everyone else has at most a binary plan-vs-act or ask-vs-build split.
  • Skills architecture: a short catalog in the prompt, full bodies loaded on demand, layered by scope. Zed and OpenHands landed near this; our per-scope cascade is a superset.

The eleven projects, one line each

Cline · Apache-2.0

Strong "emit every independent tool call now" parallelism doctrine, plan/act via message tagging, and a user-editable markdown checklist for progress.

Roo Code · Apache-2.0

Modes defined as data (named tool subsets with file restrictions, enforced at tool validation) and a strict delegation contract for subtasks.

Aider · Apache-2.0

A ranked "repo map" of the codebase, and an architect/editor split: a strong model writes the spec, a cheap model executes it.

OpenHands / agent-sdk · MIT

Deterministic keyword triggers that inject knowledge on every message, path-triggered context, and robust conversation-compaction guards.

Gemini CLI · Apache-2.0

Tools run in parallel by default (serial is the marked case), a one-sentence rule for ambiguous intent, and layered loop-detection.

Codex CLI · Apache-2.0

A disciplined plan tool (exactly one step in progress), a byte budget with precedence rules for its instructions file, and approval-escalation as a third outcome.

Goose · Apache-2.0

"Recipes": playbooks with typed parameters and machine-checkable success criteria, procedures you can verify, not just advice.

Zed · GPL (patterns only)

Tool "profiles" (write / ask / minimal, each with a default model) and the crispest parallelism wording found in the survey.

Onlook · Apache-2.0 · closest cousin

Ships the user's selected element as a structured "I am looking at this" block, and teaches the agent its own UI. No self-review loop.

bolt.diy · MIT

The strongest anti-generic language found, a ban list ("avoid templated aesthetics… no simplistic headers", "never use placeholders") and one-shot holistic output.

Dyad · Apache-2.0

A default rules document when a file has none, a tight scope trio ("don't do more than asked", "check whether it's already done"), and a plan mode with an enforced accept gate.

Top things we took from it

  • Better parallelism wording (Cline / Zed / Gemini): our worst measured metric was near-serial tool calls; this is a prompt-only fix.
  • An anti-generic "ban list" (bolt.diy): prohibitions of named generic moves, added to the nudge that fires when a file has no direction.
  • "Check whether it's already done" (Dyad): one line that stops redundant work.
  • Stop after three failed fixes (Gemini + Aider): re-approach instead of looping.
  • Adopt a plan tool: the survey's clearest verdict: all four major CLIs ship one, as passive progress the user can see without being interrupted.
